# Database schema

29 tables on PostgreSQL 16 with PostGIS 3.4. Generated by Alembic from the models
in `apps/api/src/contour_api/models/`; run `alembic check` to detect drift.

## Conventions

- **UUID primary keys.** Route and source identifiers appear in URLs, share links
  and export manifests. Sequential integers would leak catalogue size and let one
  private route be found from another.
- **Explicit index naming** (`ix_`, `uq_`, `fk_`, `ck_`, `pk_`), so migrations are
  reviewable. GeoAlchemy2's own spatial indexes use `idx_` and are excluded from
  autogenerate, which otherwise emits duplicate `CREATE INDEX`.
- **Server-side timestamps**, so rows written by the API, workers and migrations
  agree on one clock.
- **SRID 4326 storage**, with metric work done in a projected CRS via pyproj.

## Groups

### Sources and provenance
`route_source` · `route_source_version` · `source_import` · `source_licence` ·
`source_attribution` · `source_discrepancy`

Carries all twenty §2.3 fields. Source versions are never overwritten; a changed
source produces a new row. Disagreements are recorded rather than resolved by
discarding one side, and each result records the version it was computed from.

### Routes
`route` · `route_version` · `route_variant` · `route_segment` ·
`segment_attribute` · `bicycle_route_membership` · `waypoint` · `avoid_area`

`route_version` is immutable — an edit writes a new version pointing at its
parent. Four geometry columns (`geom_original`, `geom_normalised`, `geom_matched`,
`geom_generated`) are kept separate so a matched line never overwrites what a
source or user drew.

Hot attributes are denormalised onto `route_segment` for scan performance, each
paired with a `KnowledgeStatus`. `segment_attribute` holds the full set with
per-attribute provenance.

### Analysis
`elevation_sample` · `climb` · `route_score` · `validation_result`

Raw samples are stored separately from processed analysis, so smoothing or window
changes can be re-run without re-querying the source. `route_score` stores
components, not just a total.

## Two migration traps

Both are handled in the initial migration and both would silently break a
rollback:

1. The circular `route.current_version_id` → `route_version.id` foreign key needs
   `use_alter`, which autogenerate does not emit.
2. PostgreSQL ENUM types survive `drop_table`, so `downgrade` drops them
   explicitly. Without that, the next upgrade fails with "type already exists".
