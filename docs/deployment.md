# Deployment

## Requirements

PostgreSQL 16 + PostGIS 3.4, Redis 7+, Python 3.12+, Node 22+, and Valhalla
3.8.3 built from source.

Contour runs its dependencies as native services. Compose files describe the same
topology for hosts with a Docker daemon; the native path exists because the
reference environment has none.

## Building Valhalla

```bash
sudo ./infra/valhalla/build.sh      # ~21 minutes on 4 cores
./infra/valhalla/make-config.sh
```

Two deviations from upstream's documented Linux path, both commented at the point
of change:

- **Unreachable apt repositories are disabled first.** Upstream's dependency
  script runs `apt-get update` under `errexit`, so one blocked third-party
  repository aborts the whole build. Only sources that fail a reachability probe
  are moved aside, and the move is logged.
- **Python bindings are off.** Contour reaches Valhalla over HTTP, so the
  bindings add no capability, and nanobind's stub generator fails the build on a
  host whose numpy is broken or shadowed.

Configuration is generated by the installed `valhalla_build_config` rather than
committed by hand, so it always matches the schema of the engine actually built.
The generated config raises `service_limits.bicycle.max_distance` to 1,000 km and
`max_locations` to 200; see [architecture.md](architecture.md) for why.

## Configuration

Every variable is documented in [`.env.example`](../.env.example), and every
optional one states what stops working without it. Required in every
environment:

```
CONTOUR_DATABASE_URL
CONTOUR_REDIS_URL
CONTOUR_SECRET_KEY            # generate per environment
CONTOUR_TOKEN_ENCRYPTION_KEY  # Fernet key
CONTOUR_VALHALLA_URL
```

The application treats the placeholder `CONTOUR_SECRET_KEY` as a configuration
error outside development.

## Health

- `GET /health` — liveness, no dependencies. Suitable for a load balancer.
- `GET /health/components` — capability report; returns 503 only when a component
  is configured and broken, not when one is deliberately disabled.

## Deployment order

1. Apply migrations (`pnpm db:upgrade`) — backwards compatible within a release.
2. Deploy the API.
3. Deploy the web app.
4. Rebuild routing tiles only when the OSM extract changes; restart Valhalla
   afterwards.
